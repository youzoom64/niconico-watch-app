# niconico-watch-app 取扱説明書

ニコニコ生放送を監視し、録画、コメント保存、文字起こし、要約、画像生成、HTMLアーカイブ作成、公開までを行うWindows用GUIアプリです。

この説明書はGUIでの利用を前提にしています。コマンド操作は通常不要です。

## このアプリでできること

- 登録した配信者の放送開始を監視する
- 放送を録画し、録画が途切れた場合は再開する
- コメントを取得して放送ごとに保存する
- Faster-WhisperまたはWhisperXで文字起こしする
- WhisperXで話者を分ける
- 要約、感情分析、単語分析、スクリーンショット、要約画像を作る
- 放送ごとのHTMLと配信者別の一覧ページを作る
- 人物タグから、その人物が話題になった時刻へ移動する
- 作成したHTMLを設定済みのWebサーバーへ送る
- 保存済みのMP4/MKVを後から処理し直す
- 溜まった録画と生成物を一覧して、種類ごとに消す

## 1. 事前に用意するもの

### 必須

- Windows 10または11
- インターネット接続（初回セットアップ時）

Python、FFmpeg、FFprobeを事前にインストールする必要はありません。`setup.bat`がPython 3.11をプロジェクト内の`tools\python311`へ取得し、専用の`.venv`を作成します。FFmpeg一式もプロジェクト内へ自動取得します。

既に別のPythonや共通venvが入っていても使用しません。配布先のPCにPythonが一切入っていない状態からセットアップできます。

### 録画する場合

`SlNicoLiveRec`の手動ダウンロードや実行ファイルの指定は不要です。`start.bat`が公式配布元の最新版を確認し、未導入なら自動でダウンロード・展開して、niconico-watch-appへ実行ファイルの場所を設定します。

更新版が公開されている場合も、起動時に最新版を取得します。以前のSlNicoLiveRec設定がある場合は、ログイン設定を新しい版へ引き継ぎます。

- 公式配布元：[SlNicoLiveRec配布ページ](https://person-of-ehomaki.blog.jp/)
- SlNicoLiveRecの著作権その他の権利は、SlNicoLiveRecの開発・配布者に帰属します。
- このアプリはSlNicoLiveRec本体を同梱・改変再配布せず、公式配布元から公開されているファイルを自動取得します。

既に保存済みのMP4/MKVからHTMLを作るだけなら、SlNicoLiveRecは不要です。

#### SlNicoLiveRecへ自動適用される設定

導入時に次の推奨設定が自動適用されます。通常はSlNicoLiveRecを手動で設定する必要はありません。

| 項目 | 設定値 |
|---|---|
| ファイル名の書式を変更する | ON |
| Filename | `{id}_{year}_{month}{day}_{hour}{minute}{second}_{title}` |
| フォルダ名の書式を変更する | ON |
| FolderName | `{supplier_id}_{author}` |
| タイトルバー書式 | `{author} - SlNicoLiveRec` |
| 録画停止後に再録画を試みる | OFF |
| 再録画試行待機（秒） | `10` |
| 試行上限 | `0` |
| 開演待機・指定秒数まで待機する | OFF |
| 秒前まで待機 | `60` |
| 自動終了時にウィンドウを閉じる | ON |
| Debug mode | OFF |

「設定 → FFmpeg」は次のように設定します。

| 項目 | 設定値 |
|---|---|
| 録画終了後にフォーマットをMP4に変換 | ON |
| 変換後にオリジナルのTSファイルを削除 | ON |
| TSファイル削除時にゴミ箱に移動 | ON |
| 変換オプション | `-c:v copy -c:a copy` |

録画用の`user_session`は、niconico-watch-appの設定画面にある「録画用 user_session」へ入力して保存します。保存時にSlNicoLiveRecの設定へ自動反映されます。

`user_session`はログイン資格情報です。スクリーンショット、README、GitHub、チャットへ貼り付けないでください。

#### user_sessionの取得方法

通常はniconico-watch-appのGUIから取得できます。

1. メインGUIの「基本設定」を開きます。
2. ニコニコアカウント欄の「ログイン用Chromeを開く」を押します。
3. 開いたChromeで、録画に使うニコニコアカウントへログインします。
4. GUIへ戻り「ログイン完了後に取得」を押します。
5. `user_session`欄へ値が入ったことを確認します。
6. 「保存」を押します。
7. 録画に使う値は「録画用 user_session」へ入力します。SlNicoLiveRec側へ手動入力する必要はありません。

GUIで取得できない場合は、ログイン済みChromeでニコニコを開き、`F12`で開発者ツールを表示します。`Application` → `Storage` → `Cookies` → `https://www.nicovideo.jp`を開き、Cookie一覧の`user_session`にあるValueを使用します。Chromeの表示言語によっては`Application`が「アプリケーション」と表示されます。

ログアウトやセッション更新後は古い値が無効になることがあります。録画やコメント取得でログインエラーが出た場合は、同じ手順で取り直してください。

### GPUで文字起こしする場合

- NVIDIA製GPU
- 対応するNVIDIAドライバー
- CUDA対応版PyTorch

### 話者分離する場合

- Hugging Faceアカウント
- Hugging Faceトークン
- 使用するpyannoteモデルの利用条件への同意

## 2. インストール

1. GitHubページ上部の「Code」を押します。
2. 「Download ZIP」を押します。
3. ダウンロードしたZIPを任意のフォルダへ展開します。
4. 展開したフォルダー直下の`setup.bat`をダブルクリックします。
5. Python仮想環境、必要ライブラリ、FFmpegの準備が完了するまで待ちます。
6. 以後はフォルダー直下の`start.bat`をダブルクリックして起動します。

`start.bat`は、プロジェクト内の`.venv`または同梱用FFmpegが見つからない場合、`setup.bat`を自動実行します。共通venvや別フォルダーのPython環境は使用しません。

初回セットアップでは必要なライブラリをダウンロードするため、時間がかかります。

「Python 3.11 is not installed」と表示された場合は、Python 3.11をインストールしてから再実行してください。

## 3. アプリを起動する

通常は、フォルダー直下の`start.bat`をダブルクリックして起動してください。必要な環境がまだ準備されていない場合はセットアップも自動的に行うため、初めて使う場合も以後の日常的な起動も`start.bat`だけで構いません。

`scripts\start_gui.cmd`は、セットアップ済みのGUIを直接起動したい開発・保守作業向けです。通常利用では使う必要はありません。

黒い画面が開いた後、メインGUIが表示されます。黒い画面はログ表示とプロセス管理に使うため、GUIの利用中は閉じないでください。

タイムシフト処理だけを使う場合は`scripts\start_timeshift_gui.cmd`をダブルクリックします。

## 4. 最初に行う設定

メインGUIの設定画面で、次を順番に設定します。

1. 保存先フォルダ
2. 録画用user_session（SlNicoLiveRec本体と実行ファイルの場所は自動設定）
3. 監視する配信者
4. 文字起こしエンジン
5. 実行する生成項目
6. 必要であれば公開先

設定や処理状況は`data\tracker.db`へ保存されます。通常はこのDBを直接編集しないでください。

放送データは次の場所へ保存されます。

```text
設定した保存先\platform\niconico\配信者ID\broadcast\放送ID\
```

旧版の`bloadcast`は綴り間違いです。現在は正しい`broadcast`へ統一されています。

## 5. 配信者を監視する

配信者を登録して監視を有効にすると、アプリが新しい生放送を定期的に確認します。放送を見つけた後は、録画とコメント取得を開始し、放送終了後に文字起こし、要約、画像、HTML生成、公開など、選択した処理を順番に実行します。

```text
配信者を登録
    ↓
放送開始を自動検出
    ↓
録画・コメント取得
    ↓
放送終了を確認
    ↓
文字起こし・分析・画像・HTMLを生成
    ↓
設定している場合はWebサーバーへ公開
```

### 配信者を登録する

1. メインGUIの「監視配信者」タブを開きます。
2. 「配信者ID または user URL」へ、ニコニコの配信者IDかユーザーページURLを入力します。
3. 必要なら配信者名を入力します。空欄の場合は自動取得されます。
4. 「配信者登録」を押します。
5. 一覧に追加された配信者を選び、編集画面を開きます。

配信者IDは登録後の保存先や公開URLにも使われます。別の配信者として登録し直す場合を除き、通常は変更しません。

### 監視と生成内容を設定する

編集画面では、最初に次の項目を確認します。

| 項目 | 動作 |
|---|---|
| 監視を有効にする | この配信者の新しい放送を自動で探します |
| 放送終了後にHTMLを生成する | 録画とコメントを使ってアーカイブHTMLを作ります |
| この配信者では個別設定を使う | 共通設定ではなく、この配信者専用の生成設定を使います |
| 録画保存先 | この配信者の録画、音声、HTMLなどを保存する場所です |

続いて、放送終了後に必要な生成項目を選びます。例えば、文字起こしだけを保存する構成、要約と画像まで作る構成、HTMLを作ってWeb公開まで行う構成を、配信者ごとに分けられます。

- 文字起こし：Faster-WhisperまたはWhisperXを選択する
- 分析：感情分析、単語分析、要約など、必要な項目だけを有効にする
- 画像：スクリーンショットや要約画像を作る場合に有効にする
- HTML：放送ごとのページ、タグ、配信者一覧ページを生成する
- 公開：Step15を有効にし、設定済みのWebサーバーへ送る

人物名や固有名詞が多い配信者では、「使用タグ候補」へ認識させたい表記とHTMLへ表示する正式名を登録します。文字起こし設定の詳細は「7. 文字起こしを設定する」、各Stepの内容は「8. 生成項目を選ぶ」を参照してください。

### 監視を開始した後の動作

設定を保存して監視を開始すると、メイン画面で現在の状態を確認できます。

- 放送前：配信者の放送開始を定期確認する
- 放送中：放送ID、タイトル、配信者を取得し、録画とコメント保存を行う
- 録画が既に動作中：同じ放送の録画を重複起動しない
- 放送終了後：録画終了を確認し、有効な生成項目を順番に処理する
- 処理完了後：保存先へ生成物を残し、設定されていればWebサーバーへ公開する

生成物は基本設定で指定した保存先の、次のフォルダーへ放送ごとに保存されます。

```text
保存先\platform\niconico\配信者ID\broadcast\放送ID\
```

設定を保存しただけでは、既に作成済みのHTMLは変わりません。以前の放送へ新しい設定を反映する場合は、「9. 保存済み放送のHTMLを作り直す」の手順で必要なStepを再実行します。

### 迷った場合の基本設定

最初は次の構成にすると、録画からHTML確認までの流れを把握しやすくなります。

1. 「監視を有効にする」をONにします。
2. 「放送終了後にHTMLを生成する」をONにします。
3. 話者分離が不要ならFaster-Whisperを選びます。
4. 要約、スクリーンショット、放送ごとのHTML、配信者一覧ページを有効にします。
5. 人物名や固有名詞を「使用タグ候補」へ登録します。
6. Web公開が必要な場合だけStep15と公開先を設定します。
7. 「保存」を押して監視を開始します。

各設定項目の詳しい説明は、[配信者設定 取扱説明書をブラウザで見る](https://warehouse.bitter.jp/niconico-watch-app/docs/broadcaster-settings.html)を参照してください。

## 6. スペシャルユーザーを設定する

スペシャルユーザーの登録・AI分析・自動反応・配信者との紐付けは、[スペシャルユーザー設定 取扱説明書をブラウザで見る](https://warehouse.bitter.jp/niconico-watch-app/docs/special-user-settings.html)を参照してください。

スペシャルユーザーは、特定のコメント投稿者をユーザーIDで登録し、その人のコメントを放送ごとに抽出して専用HTMLへまとめる機能です。

1. メインGUIの「スペシャルユーザー」タブを開きます。
2. ニコニコのユーザーIDと表示名を入力して登録します。
3. 登録したユーザーを開き、必要な配信者と紐付けます。
4. 「HTMLを生成する」をONにします。
5. 必要に応じて「AI分析を使う」と「サーバーへアップロードする」をONにします。
6. 設定を保存します。

対象ユーザーのコメントが見つかった放送では、次のHTMLを生成します。

- リンク一覧ページ：そのユーザーがコメントした放送を一覧表示する
- 個別ページ：放送情報、対象ユーザーのコメント、基本統計、設定されている場合はAI分析を表示する

デザインは登録ユーザーごとに保存され、次回以降に生成するHTMLにも適用されます。

- 「ページデザインを編集」：放送ごとの個別ページを編集する
- 「リンクページデザインを編集」：リンク一覧ページを編集する

デザイン編集画面では、実際のHTMLと同じ構造のサンプルを見ながら、背景、文字、アイコン、縁の暗さなどを変更できます。リンク一覧ページでは、左右のパーティクルを炎または花火へ切り替え、位置、高さ、方向、広がり、重力、速度、色などを調整できます。雪パーティクルの量、大きさ、落下速度、不透明度なども変更できます。各スライダーの右側にある数値欄へ直接入力することもできます。

「保存する」を押すまでは設定へ保存されません。保存後に新しく生成するHTMLへ反映されます。

## 7. 文字起こしを設定する

### Faster-Whisper

通常の文字起こし向けです。WhisperXより構成が単純で、話者分離が不要な場合に向いています。

デバイスは自動判定されます。対応するNVIDIA GPUがあればGPUを利用し、なければCPUで動作します。WhisperXの追加インストールは不要です。

### WhisperX

次が必要な場合に使用します。

- 単語単位の時刻
- 発言者の分離
- 詳細な話者ラベル

WhisperXは任意の追加機能です。通常の`setup.bat`ではインストールされず、WhisperXを使う場合だけ`install_whisperx.bat`を実行します。対応するNVIDIA GPUやドライバーがないPCでも、WhisperXを入れずにアプリ本体とFaster-Whisperを利用できます。

### 配置場所を変更する場合

通常はZIPを展開したフォルダー内だけで動作します。外部ツールを別の場所へ置く場合だけ、次の環境変数で指定できます。

- `NICONICO_WATCH_SHARED_ENV`：認証情報を保存する`.env`の場所
- `NICONICO_SUNO_CLI_DIR`：任意機能のSuno CLIフォルダー
- `NICONICO_SUNO_PYTHON`：Suno CLIに使用するPython
- `NICONICO_CHROME_PATH`：Chrome実行ファイル
- `NICONICO_CREDENTIALS_API_PYTHON`：任意の認証APIに使用するPython
- `NICONICO_CREDENTIALS_API_WORKDIR`：任意の認証APIの配置フォルダー

GPUを使う場合の基本設定は次です。

- デバイス：`cuda`
- 計算タイプ：`float16`
- モデル：精度優先なら`large-v3`

「CUDA out of memory」が出る場合は、最初にバッチサイズを下げてください。それでも不足する場合はビームサイズまたはモデルサイズを下げます。

### 初期プロンプト

初期プロンプトは「どのような音声なのか」を文字起こしエンジンへ伝える欄です。

空欄の場合は次の文章が自動で使われます。

> これはニコニコ生放送の録画音声です

固有名詞が多い放送では「Hotwordsに含まれる語は主に人物名・固有名詞です」と加えると、文脈を補助できます。

### 認識支援文字と正式タグ

監視配信者編集画面の「使用タグ候補」で設定します。

| 認識支援文字 | 正式タグ |
|---|---|
| 文字起こしで認識させたい表記 | HTMLに表示する正式表記 |

- 左側はHotwordsとして文字起こしへ渡されます。
- 右側は一覧ページや人物タグで使われます。
- 同じ名称でよければ左右を同じにします。
- 表記を直したい場合だけ左右を変えます。

## 8. 生成項目を選ぶ

GUIではStep01～15として表示されます。チェックを外したStepは実行されません。

| Step | 内容 |
|---|---|
| 01 | 放送情報を集める |
| 02 | 音声抽出と文字起こし |
| 03 | 感情分析 |
| 04 | 単語分析 |
| 05 | 要約 |
| 06 | 音楽生成 |
| 07 | 要約画像生成 |
| 08 | AI会話生成 |
| 09 | スクリーンショット生成 |
| 10 | コメント処理 |
| 11 | 特別ユーザーHTML生成 |
| 12 | 放送ごとのHTML生成 |
| 13 | タグと一覧データ生成 |
| 14 | 配信者別一覧ページ生成 |
| 15 | Webサーバーへアップロード |

Step11の登録方法、生成されるページ、ユーザーごとのデザイン編集については、「6. スペシャルユーザーを設定する」を参照してください。

## 9. 保存済み放送のHTMLを作り直す

ローカル処理は、既に保存してある動画やDBのデータを使い、必要な工程だけを選んで実行し直す機能です。例えば、デザイン変更後にHTMLだけ作り直す、文字起こしからやり直す、Step15だけ実行して再公開するといった使い方ができます。

画面全体と各タブの詳しい操作は、[タイムシフトGUI・ローカル処理 取扱説明書](docs/timeshift-processing.html)を参照してください。

### メインGUIから対象放送を送る

確認タブから送ると、対象放送の動画を探してタイムシフトGUIの「ローカル処理」タブへ追加します。

1. メインGUIの「確認」タブを開きます。
2. 対象の配信者を選びます。
3. 作り直したい放送の行を選びます。
4. 行を右クリックします。
5. 「ローカル処理へ送る」を押します。
6. タイムシフトGUIが開いたら、Step01～11のチェックを外します。
7. Step12・13・14だけをチェックします。
8. Webサーバーも更新する場合はStep15もチェックします。
9. 「ローカル動画からHTML作成」を押します。

複数の放送を選択して一度に送ることもできます。同じLVの動画が複数に分かれている場合は一つの放送としてまとめ、放送日時が古いものから順番に処理します。

### 目的に合わせてStepを選ぶ

| やりたいこと | 選択するStep | 再利用するもの |
|---|---|---|
| HTMLの見た目だけ作り直す | Step12・13・14 | 保存済みの文字起こし、コメント、要約、画像 |
| HTMLを作り直して公開する | Step12・13・14・15 | 保存済みデータを使い、HTMLを再生成して送信 |
| タグや配信者一覧だけ更新する | Step13・14。公開するなら15も選択 | 生成済みの放送データとHTML |
| 要約から作り直す | Step05と、必要な後続Step | 保存済みの文字起こしとコメント |
| 文字起こしからやり直す | Step02と、結果を反映したい後続Step | ローカル動画と保存済み放送情報 |
| 最初から一通り処理する | Step01から必要な最終Stepまで | ローカル動画。足りないコメントはAPIから取得 |
| 公開だけやり直す | Step15 | 生成済みHTMLと公開対象ファイル |

Step01またはStep02を選ぶと、動画区間の確認、音声抽出、必要に応じた文字起こしなどの前処理を実行します。Step01・02を外した場合は動画や音声の前処理を行わず、DBと保存先にある既存データから選択したStepだけを実行します。

HTMLを作り直すローカル処理では、既存HTMLを新しい結果で上書きします。文字起こしやAI分析を残したい場合は、それらのStepを選択しないでください。

### スペシャルユーザーHTMLを処理する

スペシャルユーザーの未生成HTMLは、通常の「ローカル処理」ではなく「スペシャル処理」タブで扱います。

1. メインGUIのスペシャルユーザー確認画面から、未処理の放送をローカル処理へ送ります。
2. タイムシフトGUIの「スペシャル処理」タブへ対象が表示されます。
3. 処理する行を選択します。
4. 必要なら「AI分析を作る」をONにします。
5. 既存の個別HTMLも上書きする場合だけ「既存HTMLを作り直す」をONにします。
6. 公開まで行う場合は「サーバーへアップロードする」をONにします。
7. 「選択を処理」を押します。

「既存HTMLを作り直す」がOFFの場合、作成済みの個別HTMLは保持されます。一覧ページの補完や未生成ページの作成だけを行いたい場合はOFFのままにします。

「ローカル動画が見つかりません」と表示された場合は、対象のMP4またはMKVをタイムシフトGUIへ直接追加してください。ファイル名には`lv`から始まる放送IDが必要です。

## 10. ローカル動画・タイムシフトを処理する

タイムシフトGUIは監視アプリとは別プロセスで動き、URLからの取得と、PCに保存済みの動画の処理を行います。通常は`scripts\start_timeshift_gui.cmd`から起動します。メインGUIから放送やファイルを送った場合は、既に起動しているタイムシフトGUIへ追加されます。

初めて使う場合は、[タイムシフトGUI・ローカル処理 取扱説明書](docs/timeshift-processing.html)を開き、「やりたいことから操作を選ぶ」から確認してください。

画面には主に次のタブがあります。

| タブ | 用途 |
|---|---|
| URLから取得 | 放送URLや配信者の番組一覧URLから、タイムシフト動画とコメントを取得する |
| ローカル処理 | PCにある動画から、文字起こし、分析、HTML生成などを実行する |
| タグ修正 | 保存済み放送のタグを直し、HTMLと一覧を再生成する |
| スペシャル処理 | スペシャルユーザーの一覧・個別HTMLを生成する |
| 未アップロード | 生成済みで未公開の放送を選んでアップロードする |
| 消滅URL登録 | 削除された放送URLを一覧へ反映する |

### URLからタイムシフトを取得する

1. 「URLから取得」タブを開きます。
2. 放送URLまたは配信者の番組一覧URLを、1行に1件入力します。
3. HTMLまで作る場合は、実行するStepを選びます。
4. 動画とコメントだけ保存する場合は「動画・コメントのみ取得」を押します。
5. HTML生成まで続ける場合は「動画・コメントを取得してHTML作成」を押します。
6. 下部の処理状況で、URL解析、取得、コメント保存、HTML生成の結果を確認します。

既に取得済みのタイムシフト動画がある場合は再利用します。ライブ録画がまだ進行中の場合は、同じ放送を重複取得せず、録画終了を待ってから処理します。

### PCにある動画を処理する

1. 「ローカル処理」タブを開きます。
2. MP4、MKV、WebM、FLV、TSの動画を一覧へドラッグ＆ドロップします。「動画を追加」から選択することもできます。
3. 一覧にLV番号とファイルパスが表示されたことを確認します。
4. 実行するStepだけをチェックします。
5. Step15を実行する場合は、必要に応じて「MP3をアップロード」と「スクショをアップロード」を選びます。
6. 「ローカル動画からHTML作成」を押します。
7. 下部の処理状況で、各LVの開始工程、成功、失敗理由、生成HTMLの場所を確認します。

動画のファイル名には`lv`から始まる放送IDが必要です。例：

```text
lv350000000_配信タイトル.mp4
```

同じ放送IDの録画が複数に分かれている場合は、一つの放送として扱います。録画が途中で止まり、すぐ再開された場合も、DBの録画区間を使って時間軸を統合します。

Step01またはStep02を含む処理が成功すると、使用した元動画は生成HTMLと同じフォルダーの`archive`サブフォルダーへ移動します。動画を元の場所へ残したままHTMLだけ更新したい場合は、Step01・02を外して必要な後続Stepだけを実行します。

### 処理結果を確認する

処理状況にはLVごとに次の内容が表示されます。

- 保存済みコメントを再利用したか、コメントAPIから取得したか
- 実行するStepとスキップするStep
- 動画区間、音声抽出、文字起こしなど、現在開始した工程
- HTML、MP3、動画アーカイブなどの生成先
- 成功件数と失敗件数
- 失敗したLVとエラー内容

成功したLVは処理一覧から取り除かれ、失敗したLVは確認できる状態で残ります。タイムシフトGUIを閉じると、このGUIが開始した実行中の処理も停止します。

## 11. 作成したHTMLを見る

メインGUIの確認タブから、対象放送の生成HTMLを開けます。

配信者フォルダには次が作られます。

- `index.html`：全放送の一覧
- `tags`フォルダ：タグ別一覧
- 放送IDフォルダ：個別HTML、文字起こし、音声、画像

個別HTML上部の人物タグを押すと、その人物が話題になった場所へ順番に移動します。発言中の人物名は正式タグ名へ勝手に置換せず、元の表記を残したまま回数だけを表示します。

スマホ専用HTMLは作成しません。通常のHTMLが画面幅に合わせて表示されます。

## 12. Webサーバーへ公開する

Step15を有効にすると、設定済み公開先へHTMLを送ります。

公開設定にはサーバー名、保存先、認証情報が必要です。認証情報をGitHubや生成HTMLへ書かないでください。

公開後は次を確認します。

- 一覧ページが開く
- 個別HTMLへのリンクが開く
- 画像が表示される
- タグ別一覧が崩れていない
- 個人情報やトークンが含まれていない

## 13. よくあるエラー

### 「venv Python not found」

`setup_venv.cmd`を先に実行してください。

### 「Torch not compiled with CUDA enabled」

CPU版PyTorchが入っています。使用するCUDAに合うPyTorchを入れ直す必要があります。

### 「CUDA failed with error out of memory」

文字起こしのバッチサイズを下げます。次にビームサイズを下げ、それでも不足する場合は小さいモデルを選びます。

### Hugging Faceの認証エラー

Hugging Faceトークン、モデルの利用条件への同意、ネット接続を確認してください。

### 話者ラベルが付かない

WhisperXだけでは話者分離されません。「話者分離」にチェックを入れ、Hugging Faceトークンを設定してください。

### Step12で動画が見つからない

保存先が次の形式になっているか確認してください。

```text
配信者ID\broadcast\放送ID
```

### GUIを閉じても処理が残る

タイムシフトGUIが開始した処理は、GUI終了時に停止する設計です。残る場合はタスクマネージャーでPython、FFmpeg、WhisperXを確認してください。監視アプリ本体は別プロセスです。

## 14. アーカイブ動画と生成物を片付ける

保存先は放置すると数百GBになります。ツールバーの「アーカイブ管理」を押すと、何がどれだけ積まれているかを一覧して消せる窓が開きます。

この窓はDBを見ません。実際に置かれているファイルだけを数えるので、表示された容量がそのまま空く容量です。

### 生成物タブ

放送1件が1行です。列は「動画」「中間音声」「音声」「画像」「HTML」「作業」「その他」「合計」に分かれ、見出しを押すと大きい順に並びます。行を選ぶと、下の表に中身のファイルが出ます。

- 動画：`archive` に退避した MP4/TS。HTMLができていれば消せます
- 中間音声：`recording_segments` の WAV/MP3。文字起こし後は不要です
- 音声：`放送ID_audio.mp3`。HTMLの再生に使うので、消すと再生できません
- 作業：結合作業の残骸と `.bak`

ボタンは選んだ放送に対して働きます。「動画を削除」「中間音声を削除」「作業ファイルを削除」は種類ごと、「放送ごと削除」は放送ディレクトリを丸ごと消します。下の表で選んでからファイル単位で消すこともできます。

### 録画フォルダタブ

SlNicoLiveRec の保存先を放送IDごとにまとめて出します。「生成物」列が「あり」の録画は、同じ放送のHTMLができているので消せます。「生成物ができているものだけ」にチェックを入れると、まだ処理していない録画を隠せます。

### 削除のしかた

既定では「ごみ箱に入れる」がオンです。ごみ箱を空にするまで空き容量は戻らないので、すぐ空けたい場合はチェックを外してください。外すと完全削除で、元へは戻せません。

録画中や処理中のファイルは消せません。その分は失敗として一覧に出るので、処理が終わってからやり直してください。

## 15. データとバックアップ

重要なデータは次です。

- `data\tracker.db`：放送、コメント、文字起こし、処理状態
- 設定した保存先：動画、音声、HTML、画像
- `config.json`：共通設定

アプリ更新前には、この3か所をバックアップしてください。

APIキー、Cookie、Hugging Faceトークン、FTPパスワードを公開リポジトリへ入れないでください。

## 16. 開発者向け

通常利用者はこの章を読む必要はありません。

アプリの入口は`main.py`です。GUI、タイムシフトGUI、トラッカー、ローカルAPIをサブコマンドで起動できます。テストは`pytest`を使用します。

メインGUIの「テスト」タブでは、`tests`ディレクトリにある高速テストを項目別または一括で実行できます。録画や外部APIを動かさず、LV番号、録画ファイル選択、保存先、設定の既定値、タグ変換、時間軸、公開URLなどの純粋処理を確認します。

開発時にコマンドから全件実行する場合は、プロジェクト直下で次を実行します。

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests
```

主な補助ツール：

- `tools\run_broadcaster_step12_to_end.py`：配信者の保存済み全放送をStep12から一括処理
- `tools\regenerate_mobile_html.py`：旧スマホHTML互換ツール。通常運用では使用しません
- `tools\whisperx_transcribe_cli.py`：WhisperX文字起こし処理

## 注意事項

- ニコニコ生放送の利用規約、著作権、配信者・コメント投稿者のプライバシーを守ってください。
- 録画、文字起こし、公開は必要な権利と許可がある範囲で行ってください。
- AIによる文字起こし、要約、人物タグ、感情分析には誤りが含まれます。
- 公開前に生成HTMLと個人情報を確認してください。
